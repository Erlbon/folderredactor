# Window and graphics review, 2026-11-10 (build 2026-11-08#05)

A critical review of the Ⅎolder Redactor's window, dialogs and controls, measured against the one job the program has: drafting, checking and writing folder notes. Nothing in the program was changed. The answers go on the decision page (one card per proposal, Yes / No / Later); this file holds the same proposals and reasons.

**Overall.** The pieces are good: the matching rules, the candidate table, the link box, the before/after diff and the Local files tab all do real work. The problem is where they live. The main window is a page of instructions (`gui/main_window.py:54-60`, `:84-99`), and every step of the job is a modal dialog stacked on the last: a music-or-video question, the "which folder?" dialog, a modal progress for the whole lookup, the review page (its own 1100x700 window with two views), a summary box after each write, and a follow-up question when it closes. While any of them is open the library cannot be looked at. Folders that already have a note are not in the review at all. Closing the review page throws the drafts away. The new window fixes most of this by itself; the cards say what each control becomes.

## 1. The tree on the left

### 1. The tree shows every folder and its note state
- **What:** today the review list holds only the folders the scan proposed (`notes_review_dialog.py:695-711`). Folders with a current note, a note you edited or a note not made by this program are "left alone" and counted in one sentence (`gui/music_notes.py:154-158`). You cannot see them, open their note, or ask for a fresh draft.
- **Why:** a walker is only useful if it shows the whole library. The note state is the thing you scan the tree for.
- **Fix:** a `QTreeView` over the library (lazy: a folder's children are read when it is opened, never a background walk). One light per folder, told apart by shape as well as colour (your pick in chat, 2026-11-10: B): ● green = a current note (also a note not made by this program); ◐ amber = a draft waiting (confident, uncertain or nothing found) or an outdated note; ✎ green = a note you edited; ○ hollow grey = no note. No red: a folder without a note is not an error. The pane's header names the state in words. Alphabet grouping folders (A, B-C, 0-9) shown plain, no mark. The tick box sits on rows with a writable draft.
- **Effort:** large. **Recommendation:** Yes.

### 2. Look up runs on the selected folder, in the window
- **What:** Create Notes opens the "which folder?" dialog every time (`gui/main_window.py:271-293`, `notes_scope_dialog.py`), then a modal progress covers the window until every folder is looked up (`notes_run.py`). On a big artist folder that is minutes of a locked window.
- **Why:** with a tree, the selected folder already answers "which folder?". Drafts are worth looking at as soon as each one arrives.
- **Fix:** Notes > Look Up (also a button and the right-click menu): the selected folder, and its subfolders if "and below" is chosen. Lookups run on a worker; each folder's mark changes when its draft arrives; the status bar shows "Looking up M: 3 of 12" with Cancel. The scope dialog goes. You can review the first drafts while the rest run.
- **Effort:** large. **Recommendation:** Yes.

### 3. No music-or-video question
- **What:** if the guess fails, a box asks "Is this a music library or a video library?" (`gui/main_window.py:260-269`), and the window label says "music or video: cannot tell".
- **Why:** with the tree, the guess can be made for the selected folder when Look Up starts (`core/media_guess.py` already looks at a bounded set of names). A mixed library then works too.
- **Fix:** guess per Look Up from the selected folder; ask only if that folder's guess also fails, and remember the answer for that library.
- **Effort:** small. **Recommendation:** Yes.

### 4. What to look up: artists, albums, genres
- **What:** the kinds (genre / artist / album) are tick boxes in the scope dialog (`gui/music_notes.py:38-42`), with "Also review notes made by an older version" beside them.
- **Why:** the scope dialog goes (card 2), but the choice is real: artist notes are 5 requests each, album notes 4, and you often want only one kind.
- **Fix:** a drop-down on the Look Up button: Artists / Albums / Genres and collections / Also refresh outdated notes, remembered. On a single folder it does what that folder is, whatever is ticked.
- **Effort:** medium. **Recommendation:** Yes.

### 5. Local files under the tree, not as a note tab
- **What:** the cover, track list and tags of the folder are a fourth tab beside Preview and Raw text, and the page switches to it by itself when there is no draft (`notes_review_dialog.py:325-330`).
- **Why:** they are facts about the folder, not about the note. You want to see them next to the candidates while matching, not instead of the note.
- **Fix:** a small folder panel under the tree (cover thumbnail, "4 albums, 41 tracks", tags on demand), reading in the background as `gui/music_evidence_view.py` already does. Can be hidden from View.
- **Effort:** medium. **Recommendation:** Yes.

## 2. The note pane on the right

### 6. The pane always shows a note
- **What:** the preview shows only a fresh draft; with none it says "No draft yet" (`notes_review_dialog.py:477-483`). An existing note is only visible in the Before / after tab of an update, or with Open note in another program.
- **Why:** a pane that is always open has to show something for every folder, or it is empty most of the time.
- **Fix:** selected folder with a draft: the draft. With a note on disk and no draft: that note, with its state ("current", "edited by you"). With neither: "No note" and a Look Up button. Header line: path, note file name, state badge.
- **Effort:** medium. **Recommendation:** Yes.

### 7. Editing a note in the pane
- **What:** the pane is read-only on purpose: "the note preview (read-only: Pluteus edits notes)" (`notes_review_dialog.py:15-16`).
- **Why:** with the note always on screen, fixing a wrong year or a bad sentence in place is the obvious next wish. Against it: two places to edit the same file, and Pluteus already has an editor.
- **Fix:** **A**, keep read-only, with an "Edit in Pluteus" or "Open note" button. **B**, an Edit button that turns the Raw view into an editor; Save writes the note, it then counts as "edited by you" and lookups leave it alone (the same rule as an edit made in Pluteus).
- **Effort:** medium. **Recommendation:** B (the pane is the program now, and the edited-by-you rule already exists).

### 8. The matching controls fold into one strip above the note
- **What:** above the note text the panel stacks, one under the other: path, note line, reasons, problems, the level drop-down, the candidate caption, the candidate table (fixed at 140 px, `notes_review_dialog.py:253`), Use selected candidate, Create a minimal note from the tags, Genres covered, Link (`:342-354`). For an uncertain folder that is about half the height before the note starts (see the one-at-a-time render).
- **Why:** the note is the thing you judge; the matching controls are needed only until the folder is resolved.
- **Fix:** one "Match" strip, shown only for an unresolved folder and collapsible after: the candidates as a short list (a click or Enter builds the draft at once, so the Use selected candidate button goes), then one row with Link, Level and Minimal from tags. Reasons and problems as one line under the header, the full list in a tooltip.
- **Effort:** medium. **Recommendation:** Yes.

### 9. Preview, Raw and Before / after as a switch in the pane header
- **What:** four tabs (`notes_review_dialog.py:320-328`); Before / after appears and disappears per row, and the page moves you to Local files on its own.
- **Why:** tabs that come and go per row make the pane jump. With Local files moved out (card 5) only three views are left, and they are views of the same note.
- **Fix:** a three-way switch in the pane header (Preview / Raw / Before-after). Before-after is greyed, not hidden, when there is no old note. The choice stays when you move between folders.
- **Effort:** small. **Recommendation:** Yes.

### 10. One confidence mark, not three
- **What:** confidence is shown as a badge (`:419-420`), as coloured text in its own column (`:980`), and as a state word in a fourth column; a pending row has an empty State column.
- **Why:** three signals for one fact; the columns also make the list wide (it needs a horizontal scroll bar, always shown, `:705-706`).
- **Fix:** the tree has one mark per folder (card 1) and no columns; the badge stays in the pane header. The always-on scroll bars and the two-line hint under the list, both there to stop the old list jumping, go with it.
- **Effort:** small. **Recommendation:** Yes.

## 3. Writing

### 11. One write button, ticks in the tree, no second view
- **What:** two views of the same work (one at a time with Back / Skip / Write note / Write all remaining confident (n) / Close, and the list with Tick all confident / Untick all / Tick best guesses / Write n ticked notes / Close), switched by a link (`:628-632`, `:668-768`) and a greyed Notes > Switch View.
- **Why:** six write-or-move buttons and two layouts for one decision: is this draft right?
- **Fix:** ticks in the tree; one "Write ticked (n)" button; Enter writes the selected folder's draft and moves to the next unresolved one; Notes > Next Unresolved (F8) replaces Skip and Back. Tick all confident and Tick best guesses go to the Notes menu and the right-click menu. The one-at-a-time view and Switch View go.
- **Effort:** medium. **Recommendation:** Yes.

### 12. No summary box after each write
- **What:** every batch write ends in a summary message box (`:921-925`), and closing the page asks about album notes in another box (`:910-919`).
- **Why:** the tree already shows what was written; a box to click away after each write is an interruption.
- **Fix:** the summary goes to the status bar (and History when it is on). The album follow-up becomes ordinary: the artists just written stay selected and Look Up > Albums does the rest. The "Replace n notes made by an older version?" question stays: it moves an old note to the Recycle Bin.
- **Effort:** small. **Recommendation:** Yes.

### 13. Drafts survive until you write or drop them
- **What:** closing the review page drops every draft that was not written; only the lookup cache remains, so a second Create Notes has to run again.
- **Why:** in the new window drafts live in the tree, so this is fixed while the program runs. Across a restart it is not.
- **Fix:** keep pending drafts in memory (comes with card 2). Saving them next to the exe for the next start is a separate step, offered here as Later.
- **Effort:** medium. **Recommendation:** Later (in memory first; see whether a restart in the middle of a library is common).

## 4. Menus

### 14. Remove Clean Up (job 2)
- **What:** the README, CLAUDE.md, ABOUT.md, the window's intro text and the menu (`gui/main_window.py:141-147`) all describe a second job, checking a library's folder tree and renaming, from the plan. All three menu entries are greyed.
- **Why:** you said the notes are all this program should do. A whole greyed menu promises a job that will not come.
- **Fix:** remove the Clean Up menu and every mention of job 2; the plan's renaming steps are struck in `C:\Temp\Claude\notes-app-plan\plan.md`. The "Into a library it writes .md notes and nothing else" rule gets simpler: no renames at all.
- **Effort:** small. **Recommendation:** Yes.

### 15. The greyed entries get built or go
- **What:** greyed today: Edit > Undo, Notes > Refresh Old Notes, Notes > Switch View (`:124-139`). View > Command Palette is wired to the "not built yet" message (`:128-129`) and then also to the palette (`:165`, redactor_common `command_palette.py:249`), so it opens the palette and says "not built yet" in the status bar at the same time.
- **Why:** the family rule is "disable, never hide", but a greyed entry that will never be built is noise.
- **Fix:** Undo undoes the last note written (History's undo handler exists, `core/history.py`). Refresh Old Notes becomes the "Also refresh outdated notes" option of Look Up (card 4) and goes from the menu. Switch View goes (card 11). Command Palette loses the "not built yet" slot.
- **Effort:** medium. **Recommendation:** Yes.

### 16. Menu entries and keys for the new window
- **What:** the new window adds actions with no place yet.
- **Why:** every action needs a menu entry (the family menu lint) and the common ones a key.
- **Fix:** Notes: Look Up (F5), Write Ticked (Ctrl+S), Next Unresolved (F8), Tick All Confident, Tick Best Guesses, Edit Note (if card 7 is B). View: Folder Panel, Preview / Raw / Before-after (Ctrl+1/2/3). Right-click on a folder: Look Up, Write, Open Note, Show in Explorer. No Ctrl+Alt keys.
- **Effort:** small. **Recommendation:** Yes.

## 5. Shared code

### 17. Where the new pane lives
- **What:** the review page is redactor_common's `NotesReviewDialog`, and mp3redactor (`gui/notes_dialog.py`) and videoredactor (`gui/notes_dialog.py`) still use it for their own notes menus.
- **Why:** the family rule says shared code first, but the window layout is this program's alone, and the old apps' notes are meant to move here.
- **Fix:** **A**, build the tree and the window in folderredactor and reuse redactor_common's `ProposalPanel` (already a widget) for the pane, changed in redactor_common where cards 8-10 need it; `NotesReviewDialog` stays for the old apps until their notes menus go. **B**, rebuild `NotesReviewDialog` itself into the new shape for all three apps.
- **Effort:** medium. **Recommendation:** A (the old apps' notes are leaving; no point reshaping their dialog).

## 6. Considered and not proposed

- **A second pane or tabs for two libraries.** One library at a time is enough for notes.
- **Cover thumbnails in the tree.** Reading every folder's cover is a walk in disguise (the no-background-walks rule applies in spirit); the folder panel shows the one selected.
- **A rich Markdown editor.** If card 7 is B, plain text with the Preview switch is enough.
- **Dark-theme colours.** The badges use fixed light colours with dark text (`:61-67`), readable in both themes; worth a look only if the app gets a dark theme.
